# Modbus TCP 連線問題診斷報告

**診斷時間**：2026-02-05
**目標設備**：192.168.61.144:4196

---

## 📋 執行摘要

### 🔴 核心問題
**網路不可達 - 網段不匹配**

目標設備 `192.168.61.144` 與本機網路不在同一網段，導致無法建立連線。

### 測試結果
| 項目 | 結果 | 說明 |
|------|------|------|
| Ping 測試 | ❌ 失敗 | 100% packet loss |
| TCP Port 4196 | ❌ 失敗 | 連線被拒絕 |
| 設備掃描 (Port 4196) | ❌ 失敗 | 在所有網段均未發現設備 |
| NuGet 連線 | ✅ 成功 | API 正常，快取正常 |

   狀態: 已連線

### 目標設備配置

```
🎯 Modbus TCP 設備
   IP: 192.168.61.144
   網段: 192.168.61.0/24
   Port: 4196
   狀態: 不可達 ❌
```

### 問題分析

本機沒有任何網路介面在 `192.168.61.x` 網段：
- 本機在：192.168.211.x, 192.168.56.x, 172.22.x.x
- 設備在：192.168.61.x ❌

**結論**：網段不匹配，需要路由或修改網路設定才能通訊。

---

## 🔍 掃描結果

### Port 4196 掃描

掃描範圍：
- 192.168.56.0/24 (254 個 IP)
- 172.22.224.0/20 (4096 個 IP，實際掃描 254 個)
- 192.168.211.0/24 (254 個 IP)
- 192.168.61.0/24 (254 個 IP)

**結果**：未發現任何設備監聽 Port 4196

### 可能原因

1. ✓ **設備未開機或未連接網路**（最可能）
2. ✓ **Port 設定錯誤** - Modbus TCP 標準 Port 是 502，不是 4196
3. ✓ **IP 位址錯誤** - 設備實際 IP 可能不是 192.168.61.144
4. ✓ **設備在完全不同的網段** - 且無路由可達
5. ✓ **防火牆阻擋** - 本機或設備端

## 💡 解決方案建議

### 方案 1：確認設備實際狀態（**最優先**）

**立即檢查：**
1. ☐ 設備電源是否開啟？
2. ☐ 網路線是否連接？（檢查 Link 燈）
3. ☐ 設備面板顯示的 IP 是什麼？
4. ☐ 設備 Modbus TCP Port 是多少？（查看說明書）

**如何查看設備 IP：**
- 檢查設備 LCD 面板（如果有）
- 查看設備 Web 設定介面
- 查閱設備說明書
- 使用設備原廠配置工具

---

### 方案 2：修改 Port 設定

Modbus TCP 標準 Port 是 **502**，而非 4196。

**測試步驟：**
```powershell
# 1. 掃描 Port 502（正在執行中...）
.\FindModbusDevice.ps1 -Port 502

# 2. 如果找到設備，更新 appsettings.json
```

**修改 appsettings.json：**
```json
{
  "Modbus": {
    "IpAddress": "找到的 IP",
    "Port": 502,
    ...
  }
}
```

---

### 方案 3：修改網路設定

如果確認設備 IP 是 192.168.61.144，需要調整本機網路設定。

#### 選項 A：設定靜態 IP（推薦）

1. 開啟網路設定：
   ```
   Win + R → ncpa.cpl → Enter
   ```

2. 選擇連接設備的網路介面：
   - 如果設備接有線：選「乙太網路」
   - 如果設備接 Wi-Fi：選「Wi-Fi」

3. 右鍵 → 內容 → IPv4 → 內容

4. 設定：
   ```
   IP 位址：       192.168.61.100
   子網路遮罩：    255.255.255.0
   預設閘道：      192.168.61.1 或 192.168.61.254

   DNS：
   慣用：          8.8.8.8
   其他：          8.8.4.4
   ```

5. 測試：
   ```powershell
   ping 192.168.61.144
   Test-NetConnection -ComputerName 192.168.61.144 -Port 4196
   ```

#### 選項 B：新增路由

如果閘道支援路由到 192.168.61.x：

```powershell
# 以系統管理員執行
route add 192.168.61.0 mask 255.255.255.0 192.168.211.254

# 測試
ping 192.168.61.144
```

---

### 方案 4：檢查 VLAN 設定

如果設備在獨立 VLAN：
1. 聯繫網路管理員
2. 確認 VLAN 配置
3. 請求開通跨 VLAN 路由
4. 或將電腦移到相同 VLAN
