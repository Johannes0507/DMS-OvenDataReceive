# Modbus TCP 連線問題診斷與解決方案

## 問題優先級

### 🔴 P0 - 網路不可達（阻斷性問題）
**現象**：192.168.61.144:4196 TCP 連線逾時，Ping 也逾時

**診斷步驟**：

1. **執行網路診斷工具**
   ```powershell
   cd "C:\Users\Keith.Lee\Diamond Groups\Source Code\IoT\OvenDataReceive\Oven\OvenDataReceive"
   .\NetworkDiagnostic.ps1
   ```

2. **手動檢查項目**
   - [ ] 設備電源是否開啟
   - [ ] 網路線是否連接（檢查 Link 燈）
   - [ ] IP 設定是否正確（192.168.61.144）
   - [ ] Port 設定是否正確（4196）
   - [ ] 本機與設備是否在同一網段（192.168.61.x）
   - [ ] 是否有 VLAN 隔離
   - [ ] 設備端 Modbus TCP 服務是否啟動

3. **快速測試指令**
   ```powershell
   # Ping 測試
   ping 192.168.61.144 -n 4

   # TCP Port 測試
   Test-NetConnection -ComputerName 192.168.61.144 -Port 4196

   # 查看本機 IP
   ipconfig | findstr IPv4

   # 檢查路由表
   route print | findstr 192.168.61
   ```

**可能原因與解決方案**：

| 原因 | 解決方案 |
|------|---------|
| 設備未開機 | 開啟設備電源 |
| 網路線未連接 | 檢查並連接網路線 |
| IP 位址錯誤 | 確認設備實際 IP，修改 `appsettings.json` |
| Port 設定錯誤 | 確認 Modbus TCP Port（通常是 502 或 4196），修改 `appsettings.json` |
| 不同網段 | 設定路由或將電腦移到同一網段 |
| VLAN 隔離 | 請網管開通 VLAN 或設定路由 |
| 防火牆阻擋 | 關閉防火牆測試或新增例外規則 |
| 設備服務未啟動 | 重啟設備或檢查設備設定 |

### 🟡 P1 - NuGet SSL 問題（建置受阻）
**現象**：`dotnet run` 時無法連到 https://api.nuget.org

**診斷步驟**：

1. **檢查網路連線**
   ```powershell
   # 測試能否連到 NuGet
   Test-NetConnection -ComputerName api.nuget.org -Port 443

   # 檢查 DNS 解析
   nslookup api.nuget.org
   ```

2. **檢查 Proxy 設定**
   ```powershell
   # 查看系統 Proxy
   netsh winhttp show proxy

   # 查看環境變數
   $env:HTTP_PROXY
   $env:HTTPS_PROXY
   ```

**解決方案**：

**方案 A：使用離線還原（推薦）**
```powershell
# 如果有網路的電腦先下載套件
dotnet restore --packages ./packages

# 在離線環境使用本地套件
dotnet build --no-restore
dotnet run --no-restore
```

**方案 B：使用 HTTP（不推薦，僅供測試）**
```powershell
# 臨時繞過 SSL（僅用於測試）
$env:DOTNET_SYSTEM_NET_HTTP_USESOCKETSHTTPHANDLER=0
dotnet restore
```

**方案 C：設定企業 Proxy**
```powershell
# 如果公司有 Proxy
netsh winhttp set proxy proxy.company.com:8080

# 重置 Proxy
netsh winhttp reset proxy
```

**方案 D：使用本地 NuGet 快取**
```powershell
# 清除並重建快取
dotnet nuget locals all --clear
dotnet restore --force
```

## 故障排除流程圖

```
開始
  ↓
執行 NetworkDiagnostic.ps1
  ↓
Ping 成功？
  ├─ 否 → 檢查實體連線（電源、網路線、IP）
  │       ↓
  │       解決後重新測試
  │
  ├─ 是 → TCP Port 4196 可連線？
          ├─ 否 → 1. 確認 Port 設定
          │       2. 檢查設備端服務
          │       3. 檢查防火牆
          │
          ├─ 是 → 執行 dotnet run
                  ↓
                  能否還原套件？
                  ├─ 否 → 使用離線還原或設定 Proxy
                  │
                  ├─ 是 → 程式能否讀取資料？
                          ├─ 否 → 檢查 Modbus 設定
                          │       (UnitID, Register Address)
                          │
                          └─ 是 → ✅ 問題解決
```
